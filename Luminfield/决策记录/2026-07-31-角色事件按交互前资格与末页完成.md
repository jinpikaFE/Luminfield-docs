# 角色事件按交互前资格与末页完成

## 背景

阶段 B 需要让关系点数产生可重复验证的角色故事结果。普通村民交谈会在首次
见面时写入相遇状态，并在每日第一次交谈时增加关系点；如果事件在这些副作用
之后判断，首次见面或本次加成就可能提前触发事件。

## 决策

- `CharacterEventCatalog` 使用稳定事件 ID，数据化定义 NPC、关系阈值、场景、
  对话页和可选前置事件。
- `GameSession` 在调用普通村民交互前，用当前相遇、关系、场景、时间、目标和
  工具状态做无副作用资格判定；普通交互成功且不是赠礼后，才激活已判定事件。
- 事件复用 `VillageSystem` 的人物投影、关系和交谈结果，不创建第二份 NPC、
  关系或场景状态。
- 当前激活事件属于瞬时会话状态，不直接写入存档。只有对话最后一页关闭后，
  `GameSession.CompleteCharacterEvent` 才保存稳定事件 ID 与完成日期。
- 后续阶段要求前置事件在更早日期完成；同日不能连续完成两阶段。
- `schemaVersion: 1` 保持不变。旧存档获得空事件列表；未知、重复、孤立和同日
  乱序记录在载入时过滤。

## 原因

- 资格基于交互前事实，避免首次见面或本次关系加成改变本次可见结果。
- 末页完成确保玩家真正读完事件，不会因预览、打开第一页或中途退出而落盘。
- 稳定 ID 与完成日期足以支持一次性事件和跨日顺序，同时保持加法存档兼容。
- 继续复用村民领域状态，避免场景节点或事件系统维护容易漂移的平行人物数据。

## 影响

- 新角色事件必须同时定义只读资格、对话页、稳定 ID、完成顺序、本地化和存档
  归一化测试。
- 赠礼、错误工具、错误场景、未认识人物和关系不足都不得激活事件或写完成状态。
- 多页对话 UI 可以复用到后续事件，但最后一页回调仍是唯一完成边界。
- UI 逐页自动按键端到端测试尚未建立；当前由回调代码路径、领域测试和 macOS
  真实试玩共同验证。
