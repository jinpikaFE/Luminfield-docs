# 稳定 ID 与数据驱动内容目录

## 背景

项目包含物品、作物、品质、资源、场景、人物、邮件、事件、机器、配方、委托和建筑。若身份依赖翻译文本、节点名称、图集位置或集合顺序，改名、换图和本地化都会破坏存档与规则。

## 决策

1. 所有需要跨帧、跨场景或跨存档识别的实体使用稳定字符串 ID。
2. 静态定义集中在 `Definitions.cs` 或对应系统 Catalog，运行时状态只保存 ID 与必要进度。
3. 本地化文本、纹理、图集索引、场景节点和瞬时路径不得作为业务身份。
4. 读取存档时按当前目录过滤未知 ID、去重并归一化。
5. 新内容的 ID 一旦进入可发布存档，不因显示名或素材替换而改变。

## 原因

- 中英文显示和业务身份完全分离。
- 数据定义可以复用在预览、动作、UI、测试和存档迁移中。
- 替换原创素材或调整地图表现不会破坏进度。
- 未知旧内容可以安全过滤，而不是让场景节点崩溃。

## 后果

- 新物品、人物、机器或事件必须同时登记定义、本地化、存档归一化和测试。
- ID 变更属于存档迁移，不是普通重命名。
- 容易从稳定状态推导的值不重复写入存档。
