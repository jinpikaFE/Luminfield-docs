# 统一目标预览与动作规则

## 背景

旧目标区始终绘制相同的青绿色格子，不知道前方是树、水面、农田还是作物，也无法表达当前工具是否匹配。实际动作已经区分手、铲子、柴刀、浇水壶和水桶，但玩家只能按下交互键后通过失败提示猜测规则。

## 决策

1. `GameSession.PreviewSelectedTarget` 作为全部面向目标格行为的无副作用预览入口。
2. `TargetPreview` 返回真实目标格、`Available`、`NeedsTool`、`Blocked` 或 `Neutral` 状态、对象种类和本地化文本键。
3. 可执行状态使用青绿色并显示 `E · 动作`；需要工具使用暖金色；资源或容量不足使用玫红色；普通格只保留弱化目标框。
4. 场景层通过 `TargetPreviewKind` 高亮树、晶体、水面、作物、人物、门、设施与床的实际范围。
5. 邻接交互的真实对象位置优先于玩家朝向格，预览位置必须和输入判定一致。
6. 根目录 `AGENTS.md` 将预览、动作、轮廓、本地化和测试定义为后续交互功能的成套交付要求。

## 原因

- 玩家在执行前即可知道“能做什么、需要什么、为什么不能做”，减少试错和无效失败提示。
- 预览与动作共同读取 `GameSession` 的领域状态，避免 UI 维护一套容易漂移的工具映射。
- 对象级轮廓在高密度生成地图中比单格方框更容易区分树、晶体、水面和设施。
- 项目级约束能确保钓鱼、采矿、开箱和新设施延续同一交互语言。

## 约束

- 预览方法不得扣体力、消耗物品、修改地图、推进任务或写入存档。
- 新增动作时不能只增加失败提示，必须同步增加目标预览和双语键。
- 视觉状态只表达领域规则，不得反向成为业务状态来源。

## 验证

- C# 编译通过，0 错误、0 警告。
- 核心测试 30/30 通过，覆盖开垦、砍树、打水、成熟作物和状态切换。
- Godot 资源导入与 `--playtest-target` 无界面启动通过。
- macOS 实机通过：青绿 `E · 开垦`、树木对象 `E · 砍伐` 正常显示；开垦后体力从 100 降至 98，提示立即切换为暖金色“选择种子播种”。
