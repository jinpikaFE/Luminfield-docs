# 生成素材按职责分层与引用规则

## 背景

`assets/generated/` 曾在根目录平铺 NPC、玩家、作物、动物、节庆、建筑、功能点、UI 和世界背景。资源增长到 146 张 PNG 后，仅凭文件名难以判断所有者、运行时职责和历史状态，也容易在新增素材时遗漏相邻源图、导入描述或引用更新。

## 决策

1. `assets/generated/` 根目录只保留说明文档，生成资源按运行时职责进入 `activities/`、`animals/`、`characters/`、`farming/`、`features/`、`locations/`、`ui/`、`world/` 或 `legacy/`，再按系统/场景细分。
2. 色键源图、最终运行图和对应 `.png.import` 放在同一最末级目录；背景、实体图集和同功能图标尽量保持相邻。
3. 代码和场景只引用明确指定的运行时资源；需要直接加载 `*_chroma.png` 时必须记录其色键材质用途。
4. `legacy/` 只保存当前运行时不加载的历史来源；重新启用前必须先迁入真实职责目录并完成全套接入验证。
5. 移动资源必须同步更新全部 `res://` 引用、Godot `source_file` 与路径哈希、仓库文档和本 Vault 的素材模块；稳定业务 ID、图集索引和存档语义不随目录变化。
6. 迁移完成后必须检查根目录无 PNG、PNG/导入描述一一对应、旧路径为零、`legacy/` 无运行时引用，并执行 C# 编译、核心测试、Godot 导入/启动和差异卫生检查。

## 原因

- 职责目录直接回答“谁使用这张图”，比按日期、阶段或工具归档更适合代码检索与长期维护。
- 源图、运行图和导入描述同目录，降低只移动其中一部分导致资源丢失或 UID 漂移的风险。
- `features/` 为委托、施工、邮件、加工、关系、星灯、储物等功能点提供明确入口，不再与 NPC、地点或世界背景混放。
- `legacy/` 具有清晰的不可加载边界，历史追溯不会意外恢复旧业务或平行状态。
- 目录结构只改变表现资源的位置，不改变稳定 ID、Core 状态所有权和存档契约。

## 后果

- 新生成素材不能直接放在 `assets/generated/` 根目录；新增职责子域时同步维护 `assets/README.md` 与 `assets/generated/README.md`。
- 移动或重命名 PNG 属于需要完整引用与导入验证的维护变更，不能只依赖编辑器自动发现。
- 现有 146 张 PNG 分布在 33 个最末级目录；后续新增资源应沿用相同职责路由，不为单次里程碑另建阶段目录。
- 路径不作为业务身份；业务与存档继续使用稳定 ID，图集只承担视觉投影。
