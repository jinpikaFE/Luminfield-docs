# 固定工具栏与背包分层

## 背景

旧版把 8 格快捷栏同时当作完整背包，首格为锄头。玩家进行普通交互或收获时若仍选中锄头，会收到“不可开垦”的反馈；加入大世界后，开垦、砍树、挖水晶、浇水和取水也需要清晰、可扩展的工具语义。

## 决策

1. 背包固定为 24 格，第一行 8 格同时是可选择的快捷栏。
2. 前五格固定为手、铲子、柴刀、浇水壶和水桶；选中范围只在前 8 格内循环。
3. 手统一承担交谈、设施交互和成熟作物收获；铲子承担开垦与挖水晶；柴刀承担砍树；水桶只从真实水源为浇水壶补水。
4. 浇水壶容量固定为 12，只有成功浇水时才消耗水量。
5. 世界资源以稳定格 ID 记录移除状态，采集必须按“验证目标与容量 → 扣体力 → 发放物品 → 移除资源”执行。
6. 存档继续使用 `schemaVersion: 1` 的向后兼容扩展；旧 `hoe` 自动迁移为 `shovel`，旧物品按顺序装入新背包，选中项按物品语义恢复。

## 原因

- 首格手势让默认状态与玩家最常见的交谈、查看和收获行为一致，避免误报工具失败。
- 工具职责拆分后，目标、反馈、体力和掉落规则都能由稳定 ID 驱动，便于继续加入矿石、木材与区域资源。
- 保留 8 格快捷栏和原数字键操作，避免改变既有教程手感；扩大到 24 格解决采集和经济循环的容量不足。
- 对版本 1 做加法式迁移能保留当前试玩存档，不需要强制清档。

## 约束

- 前五件工具不可移除或换位。
- 当前背包只支持自动堆叠和查看，不支持拖拽排序、拆分堆叠或丢弃。
- 已采集的树木和水晶当前不会按天再生；资源再生应作为独立玩法规则设计。

## 验证

- C# 编译通过，0 错误、0 警告。
- 核心测试 28/28 通过，覆盖固定顺序、旧存档迁移、工具不匹配、资源持久化、水桶取水和背包容量。
- Godot 资源导入与无界面背包场景启动通过。
- macOS 实机验收通过：五件工具、新道路与背包正常显示；柴刀砍树后体力从 100 降至 96、树节点消失并获得 2 份微光木。
