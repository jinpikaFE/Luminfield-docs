## 标准实现验证

每次相关代码改动至少执行：

1. C# 编译。
2. Core 测试。
3. 本地化键集合检查。
4. Godot headless 资源导入与主场景启动。
5. 与本次功能相关的确定性试玩入口。
6. `git diff --check`。

目标高亮、生成美术、像素缩放或布局变化还必须在当前 macOS 实际查看。存档改动必须增加新档、旧档、未知 ID、损坏数据和保存往返测试。原子动作必须覆盖成功、资源不足、容量不足、重复操作和失败零副作用。

## 试玩入口规则

- `PlaytestScenarioRegistry` 使用精确、区分大小写的 flag。
- 多个已知 flag 同时存在时，按注册顺序选择第一个。
- 无已知 flag 时保持正常标题启动。
- 场景注册表只负责选择预置状态；`Main.CreatePlaytestScenarioRegistry()` 绑定设置方法。
- 新入口必须增加目录、唯一性、优先级和正常回退测试。
- 试玩不得写死正常系统应由日程、定义或领域状态解析的结果。

## 发布与打包

- 标准三平台导出入口：`./scripts/export_all.sh`。
- 产物位于 `builds/macos/`、`builds/windows/` 和 `builds/linux/`，目录已忽略。
- “导出成功”“包结构通过”“目标平台实机通过”必须分开报告。
- 只有保存/提交的确定源码状态才适合作为可追溯发布基线。
- 未明确授权时不自动发布、创建版本或上传外部平台。
