# 经济、加工与库存

## 库存基线

- 背包共 24 格，前 8 格为快捷栏。
- 前五格固定为手、铲子、柴刀、浇水壶和水桶。
- 物品通过稳定 ID、最大堆叠数和物品类别定义；翻译文本不参与身份判定。
- 新物品必须通过 `Inventory` 进入或离开，不允许场景直接修改槽位。
- 木箱每个 16 格，位置和内容独立持久化。

## 经济与交换系统

| 系统 | 入口 | 原子边界 |
| --- | --- | --- |
| 制作 | `CraftingSystem` | 完整材料移除与产出入包一起模拟 |
| 加工 | `ProcessorSystem` | 每台机器独立；批量领取全部成功或全部不变 |
| 星辉货箱 | `ShippingBinSystem` | 投入、撤回和睡眠结算不丢物 |
| 暮光商铺 | `TwilightEmporiumSystem` + `GameSession` | 场景、营业、库存、金币和容量全部通过后再购买 |
| 每日委托 | `DailyCommissionSystem` | 交付成功后才扣物并增加金币 |
| 每周委托 | `WeeklyCommissionSystem` | 最终材料与物品奖励先交换，成功后再加金币 |
| 星灯贡献 | `StarlightSystem` | 只扣定义允许且仍缺少的完整贡献 |
| 建设施工 | `ConstructionSystem` + `GameSession` | 金币与材料一次检查、一次扣除 |
| 星邮附件 | `MailSystem` | 背包能放下完整附件后才标记领取 |
| 果树与辉巢 | `OrchardSystem` + `GameSession` | 树苗/辉巢消耗、果实/星蜜入包和容量检查成功后才提交 |
| 食材柜 | `KitchenSystem` + `GameSession` | 背包与 24 格 pantry 全批模拟后再双向转移 |
| 烹饪与食用 | `KitchenSystem` + `GameSession` | 跨 pantry/背包按品质规划，输出容量成功后一次提交；满体力不消耗料理 |
| 月辉农典折扣 | `CollectionSystem` + `GameSession` | 20/20 奖励领取后，只有 20 种普通作物种子按 `ceil(base×0.9)` 购买；两家商店的显示与扣款读取同一价格函数 |
| 月炉食录体力 | `CollectionSystem` + `GameSession` | 4/4 奖励领取后，四道既有料理各额外恢复 5 点体力；厨房面板与实际食用读取同一有效值，售价不变 |
| 星辉估价册增值 | `CollectionSystem` + `GameSession` + `ShippingBinSystem` | 工艺品 4/4 奖励领取后，蜜饯/药剂/夜茶/星蜜直售与货箱统一按 `ceil(base×1.1)` 结算；历史明细保存结算单价，不受后续奖励状态影响 |

暮光商铺的季节种子供应现先过滤当季限定种子，再以季内周偏移稳定轮换四项库存。芽辉季、雨幕季和星熟季都只轮换各自四种季节种子；长夜季在对应种子进入数据目录前保留原兼容回退。

第二次小屋升级完成后，24 格食材柜接受 Produce、Artisan、星羽蛋/凝露乳家族与
CookedDish，拒绝种子、饲料、资源、工具、设施和月绒。四道料理从普通→莹润→
星辉→共鸣家族中选料，同一实际 ID 先用食材柜；成品只入背包并可恢复体力。

## 三台加工机

- 月井凝炼器、棱彩蜜渍缸和织星烘叶机使用稳定机器 ID。
- 每台保存配方、剩余夜数和完成态，互不覆盖。
- 当前加工链包括星芽莓蜜饯、月辉根药剂与云纹夜茶。
- 当前果园经济链包括芽辉季树苗购买、月梅采摘、辉巢制作、星蜜采集，以及月梅/星蜜作为可出售物进入货箱或商店价值结算。
- 旧单队列数据只在没有合法现代机器记录时迁入主机器。
- 新机器占用的格子不能使旧档中原本合法的木箱或装饰物消失。

## 物品家族与品质

- 普通、莹润和星辉品质使用独立稳定物品 ID。
- `DataCatalog.BaseItemId` 和物品家族用于教程、委托、加工与星灯的跨品质识别。
- 需要消耗同一作物家族时优先使用低价值品质，避免无意吞掉高价值收成。
- 货箱、商店和存档继续保留真实品质 ID 与对应价值。
- 货箱待售队列不预存可变奖励价；睡眠结算时由 `GameSession.SalePrice` 冻结当时单价到历史明细，旧档缺单价时安全回退目录基础售价。

## 不变量

- 材料不足、金币不足、闭店、重复领取、机器未完成或容量不足时不发生部分变化。
- 固定工具不会被普通恢复、交换或堆叠逻辑移走。
- 货币变化必须和成功业务动作绑定，不能由 UI 按钮自己结算。
- 批量操作必须在库存副本上模拟所有输入与输出。
- 新经济入口必须明确出售、购买、奖励或只读设施中的哪一种；只读设施不得悄悄扩展经济契约。

## 验证入口

- `Inventory.TryExchange`、`TryRemoveMany`、`TryRemoveFamilies`、`TryAddMany` 相关测试。
- 制作、木箱、货箱、每日/每周委托、商铺、星灯、建设与邮件的容量/重复/不足测试。
- `--playtest-multi-processor` 和 macOS 截图 107。
- 雨幕/星熟库存、料理跨容器原子性、纯食材柜输入、pantry 归一化、施工前置、体力上限，以及月辉农典/食录/星辉估价册奖励、直售/货箱统一价格、历史结算单价往返与失败原子性由全量核心测试覆盖；当前 501/501。
