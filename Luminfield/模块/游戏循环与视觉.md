# 游戏循环与视觉

> [!note] 文档职责
> 本页保留为当前综合玩法与视觉验收快照。架构、状态所有权、存档和原子动作的长期约束分别以 [[Luminfield/模块/架构总览|架构总览]]、[[Luminfield/模块/状态所有权与依赖方向|状态所有权与依赖方向]]、[[Luminfield/模块/存档与兼容迁移|存档与兼容迁移]] 和 [[Luminfield/模块/交互预览与原子动作|交互预览与原子动作]] 为导航入口。

## 核心循环

当前教程流程：

```text
与米菈交谈
  → 获得 5 个星芽莓种子
  → 耕作 3 格
  → 播种 3 株
  → 浇水
  → 睡眠跨日并成长
  → 收获 3 个星芽莓
  → 返回米菈完成任务
```

时间从 06:00 推进至 22:00；现实 2.5 秒对应游戏内 10 分钟。日期按七日星期循环，HUD 同时显示星期、当前天气和次日预报。睡眠依次结算货箱收入与已浇水作物、清除浇水状态、增加日期、推进天气、恢复体力并保存；雨天会以零体力、零水量消耗自动浇灌已开垦土地，长夜雪不自动浇水并让户外玩家移动乘 0.85，室内保持 1.0。

教程完成后进入可重复经营循环：

```text
种植并收获二十种原创作物
  → 直接出售，或在三台固定加工机投入对应原料
  → 独立过夜完成星芽莓蜜饯 / 月辉根药剂 / 云纹夜茶
  → 单机领取或原子领取全部已完成产物
  → 在暮光商亭出售加工品
  → 用微光币购买新种子并扩种
```

暮光商亭以数据目录中的固定价格单件买卖二十种种子和对应收获物；曦绫花、辉荚藤、雾歌薄荷和彗纹薯只在芽辉季出售与播种，涟光菇、潮晶芋、灯穗苇和雨幕莲只在雨幕季出售与播种，鎏金芽、日藏瓜、冠星藏红花和琥珀缕果只在星熟季出售与播种，原有八种作物继续跨季以兼容教程与旧存档。三个已有农业季节各自按季内周次稳定轮换当季四种种子。三台加工机分别保存独立配方、剩余夜数和完成态，云纹叶新增两夜加工链“云纹夜茶”。

成功开垦、播种、浇水与收获会获得耕作经验并推进 0–5 级技能。达到 3 级后永久选择“守露人”（浇水少耗 1 点体力，最低 1 点）或“共鸣学者”（成功收获经验增加 50%）；失败动作不获得经验。

月梅果树与辉巢提供更长节奏的农场布置循环：

```text
在芽辉季购买月梅树苗
  → 在农场空闲种植床放置树苗
  → 睡眠推进三夜成长为月梅树
  → 用“手”采摘月梅
  → 两夜后再次结果
  → 制作并放置辉巢
  → 邻近成熟月梅树后跨夜产出星蜜
  → 用“手”采集星蜜
```

果树和辉巢拥有独立真实对象高亮与碰撞/占位；树苗不足、季节错误、工具不匹配、背包容量不足、材料不足或重叠放置时不会消耗任何物品或体力。

玩家也可把可出售物投入农场的星辉货箱。睡眠时货箱一次性结算，夜间总结画面按物品列出数量、小计、总收入、新日期与次日预报；睡眠前可以撤回，背包容量不足时保持货箱原状态。星辉估价册领取后，蜜饯、药剂、夜茶和星蜜的直售/货箱单价统一向上取整增值 10%；夜间结算会保存当时单价，之后的奖励状态变化不会改写历史。

月辉档案馆研究台现提供作物、料理、工艺品与采集物四个完成分类。未发现项仅显示现有图标的深靛剪影；采集物只有在真实空手拾取并成功进入背包后登记，已发现项显示季节、区域、售价与来源。芽辉、雨幕、星熟、长夜各两种采集物每天在低语林地/星辉草甸各刷新一株，星尘风各增加一个槽；同日存读保持节点，次日替换不累积。星路采集册只标记已探索区块内当日未采节点。当前完整图鉴进度为 4/8。

二十种作物共享品质与施肥循环：

```text
采集微光木与晶辉碎片
  → 制作 2 份星壤肥
  → 对已开垦、未播种的空土施肥
  → 播种时写入稳定品质抽取
  → 成熟后收获莹润品质，少量成为星辉品质
  → 按实际品质进入背包、加工、委托、货箱和商店
```

普通品质保留原有收获物稳定 ID；莹润与星辉品质使用独立稳定 ID 和递增售价。肥料保证至少莹润品质，稳定抽取的 20% 区间成为星辉品质；抽取结果随农田状态存档，读档不会重抽。肥料只作用于一茬作物，收获后清除。

采集得到的微光木和晶辉碎片还可进入制作与布置循环：

```text
采集微光木和晶辉碎片
  → 在星织制作面板制作储物箱、道路、围栏、火炬或洒水器
  → 自动移入并选中可用快捷栏
  → 在家园对应地面预览并放置
  → 通过储物、布局、照明与四向自动浇水减少重复劳动
```

每天还会生成一项确定性轮换的委托：

```text
在星灯委托板接取种植 / 采集 / 交付任务
  → 成功动作或当前背包数量推进进度
  → HUD 持续追踪
  → 当日完成后返回委托板领取微光币
  → 未完成委托在睡眠后过期并轮换
```

同一块星灯委托板还提供按周推进的长期委托：

```text
接取“星路修复”
  → 种植 3 株星芽莓
  → 采集 4 份微光木
  → 交付 3 份晶辉碎片
  → 原子领取 120 微光币与 4 份月石道路
  → 同周睡眠保留进度，第 7 天进入第 8 天时刷新
```

低语林地还提供第一条长期修复循环：

```text
用“手”开启林地守望星灯
  → 分批提交 3 种不同成熟作物
  → 分批提交微光木与晶辉碎片
  → 提交两种加工品和一个星织储物箱
  → 三个星图节点全部点亮
  → 星灯永久复苏，低语林地树木改为 4 天再生
```

## A–F 完成闭环

- 阶段 C：既有 14 天芽辉季、播种祭、星羽鸡和三档品质蛋之上，新增月珠压蛋机；每份任意品质星羽蛋一夜原子加工为星羽凝脂，失败与满包不修改库存或机器。
- 阶段 D：水域交互进入控线小游戏；钓竿、鱼饵、浮标、蟹笼、0–5 级垂钓经验和两种永久专精共享 24 鱼目录、图鉴与月水星灯，只有成功结算登记鱼类。
- 阶段 E：固定五室勘探的深度锚连接十二室确定性深矿；3/6/9/12 室保存稳定锚点，六类敌人、三种武器、四档星铲与晶矿/守夜两项技能分别持久化，失败保留最近锚点。
- 阶段 F：第八个预设施工项目六辉星门要求六灯、工坊、温室和第二次小屋升级；五夜完工后空手调律，面板开放家园与五个外围区域，传送只落在目录中的安全格。
- A–F 的新增状态继续通过 `GameSession` 编排，存档保持 schema-v1 加法兼容；生成图只负责视觉，预览与动作共用同一业务检查。

## 状态所有权


- `GameSession` 是唯一全局业务入口。
- `GameClock` 拥有日期和日内时间。
- `Inventory` 拥有 24 格背包、顶部 8 格快捷栏、选中格和堆叠规则；前五格固定为手、铲子、柴刀、浇水壶和水桶。
- 两个配置化 `FarmSystem` 实例分别拥有室外与月露温室的 `FarmTileState` 字典；`FertilizerId`、`QualityRoll`、`PlantedDay` 与 `ResonanceItemId` 记录肥料、稳定品质、播种日和已解析共鸣产物，持续采收作物按定义保留植株与单株品质状态。温室忽略季节播种限制但不接受室外天气浇水或天气共鸣。
- `OrchardSystem` 拥有月梅果树和辉巢状态；果树保存稳定位置、成长夜数、可采摘与复果进度，辉巢保存稳定位置、产蜜进度与待领取状态。
- `WorldResourceSystem` 拥有树木与水晶的耗尽日期，并统一处理工具匹配、体力消耗、采集掉落和按类型再生；水晶 2 天后、树木 7 天后重新出现。
- `CalendarSystem` 由日期推导周数、星期、四个 14 天季节、季节日和年份；`WeatherSystem` 拥有当前天气与确定性次日预报。
- `ShippingBinSystem` 拥有待售队列、撤回与夜间结算，并通过 `Inventory` 保证物品移动的原子性；历史结算行额外保存结算时有效单价。
- `CraftingSystem` 依据稳定配方 ID 检查材料；成功制作通过 `Inventory.TryExchange` 一次性提交，失败不产生部分扣除。
- `StorageSystem` 拥有家园木箱位置与每箱 16 格物品；放置、存入和取出都先检查目标与容量，再原子修改背包和木箱状态。
- `FarmObjectSystem` 拥有月石道路、星木围栏、星光火炬和露滴洒水器的稳定位置；预览与动作共用放置检查，道路可通行，其他三类参与碰撞，洒水器在作物夜间成长前浇灌相邻四格。
- `DailyCommissionSystem` 按日期选择稳定模板，拥有接取、进度、过期和领奖状态；交付委托从 `Inventory` 派生展示进度，领奖时原子扣除物品并增加微光币。
- `WeeklyCommissionSystem` 独立于每日委托保存周数、当前阶段、进度与领取态；只允许当前阶段推进，最终领奖先通过一次 `Inventory.TryExchange` 同时扣除晶辉碎片并加入月石道路，成功后再增加微光币并标记领取。
- `TwilightEmporiumSystem` 统一判定普通日 10:00–18:00 的营业边界，并按季节与绝对周次确定性提供四项种子库存；门、货单预览、打开和购买动作读取同一规则。
- `ConstructionSystem` 拥有按稳定 ID 排列的施工项目组合、每项目剩余夜数与完成态，并全局只允许一个项目施工中；第一次小屋升级、家园工坊与月露温室都先完整校验访问位置、前置、金币和材料，再以一次可观察提交原子扣除，睡眠只推进当前项目。家园工坊三夜完成后启用真实工作台；月露温室再经四夜完成，开放独立室内与 24 格跨季农业。
- `StarlightSystem` 按稳定星灯 ID 拥有林地、家园与草甸三座星灯的发现、节点贡献和永久奖励；背包节点先计算仍可接受的物品家族，再通过 `Inventory` 原子扣除。草甸节庆回响不复制节庆状态，而由 `GameSession` 从 `Festival.Results` 提供只读完成上下文；三节点完整后只激活一次，远香授粉把辉巢有效距离从 4 格扩大到 6 格。
- `VillageSystem` 拥有 16 名人物的相遇、关系和每日互动记录；`VillageCatalog` 选择灯憩日、实际天气、季节与基础条件目标，`NpcScheduleSystem` 每 10 游戏分钟批量推进四方向路径、玩家占位和跨场景安全入口，场景不保存平行业务状态。
- `MailSystem` 拥有欢迎信与按相遇、关系阶段或角色事件完成条件投递的关系邮件；次日投递读取 `VillageSystem` 与 `CharacterEventSystem` 条件，附件通过 `Inventory` 原子领取。
- `CharacterEventSystem` 拥有 16 条独立的两阶段角色事件链、完成日期和当前瞬时事件；资格按交互前状态纯判定，只有多页对话最后一页关闭后才写入完成状态。
- `QuestSystem` 拥有教程阶段与计数。
- `ProcessorSystem` 以稳定机器 ID 拥有三台加工机的独立配方、剩余夜数与待领取状态；批量领取先模拟完整背包结果，旧版单队列只在没有合法现代机器记录时迁入主机。
- `FarmingSkillSystem` 拥有 0–5 级经验、动作经验表和 3 级永久专精；`GameSession` 只在成功农业动作后记账，并统一应用浇水体力与收获经验效果。
- `GameSession` 拥有微光币，并提供原子化购买、出售、单机加工、单机领取和批量领取接口。
- `SaveService` 负责 `GameSaveV1` 的原子写入、版本检查和损坏文件保留。
- HUD 仅订阅事件，不直接修改农业或任务状态。

`GameSaveV1` 继续使用 `schemaVersion: 1`；微光币、加工机列表、耕作技能、天气、货箱队列、`Storage.Chests`、`FarmObjects.Objects`、`Orchard`、`Commission`、`WeeklyCommission`、`Construction.Projects`、`Starlight`、`Village.MetNpcIds`、`Village.Relationships`、`Mail.Entries`、`CharacterEvents.Entries`、玩家场景位置、农田 `FertilizerId`、`QualityRoll`、`PlantedDay` 与 `ResonanceItemId` 都是向后兼容的加法字段。旧存档缺失时分别恢复为安全初始值、三台空闲机器、0 级无专精、按日期推导的天气、空储物/放置物/果园列表、当日确定性委托、当周确定性委托、未施工、空星图节点、空村民/邮件/事件记录与未施肥/未抽取状态，不静默清除其他已有状态；旧施工根字段只提升和镜像第一次小屋升级，新项目列表按稳定 ID 合并并确定性保留最多一个施工中项目。旧单加工队列只在没有合法现代机器记录时迁入月井凝炼器，未知机器、果树、辉巢、非法专精、未知施工/村民/邮件/事件 ID、孤立或同日乱序事件、重叠放置物或地面不匹配的放置物会被过滤，其他进度保持不变。完成升级后若旧存档位置落入新增厨房阻挡区，恢复时迁移到小屋安全落点；未升级旧档继续沿用原桌面碰撞，不会把合法站位卡死。

工具、背包和资源状态同样以向后兼容字段加入 `schemaVersion: 1`：旧存档中的 `hoe` 在载入时迁移为 `shovel`，原有种子和产物自动装入新背包；缺失的浇水壶水量使用安全默认值。旧存档的 `RemovedNodes` 会迁移为“从载入当天开始计时”的耗尽记录，避免永久消失，也不会在载入瞬间错误重生。

## 工具与背包

- 快捷栏第 1–5 格固定为手、铲子、柴刀、浇水壶和水桶；数字键、鼠标滚轮或手柄只在顶部 8 格快捷栏中切换。
- 手负责交谈、设施交互和成熟作物收获，不再把普通交互误判成开垦失败。
- 铲子在家园农田开垦，在大世界挖掘水晶；柴刀砍伐可采集树木。工具不匹配、体力不足或背包已满时都不会修改世界状态。
- 浇水壶容量为 12；只有成功浇水时消耗 1 份水。选中水桶并对准池塘或大世界水域可把浇水壶补满。
- 背包共有 24 格，第一行 8 格同时是快捷栏；`B`、`Tab` 或手柄 `Y` 打开背包查看容量、物品数量和说明。当前版本自动堆叠，不提供拖拽换位。
- `C`、手柄 `X` 或背包顶部按钮打开制作；当前六个稳定配方产出星织储物箱、月石道路、星木围栏、星光火炬、露滴洒水器和星壤肥，面板按配方逐项显示所需与持有数量。
- 制作成功后储物箱优先移入快捷栏第 6–8 格并选中，不会覆盖前五件固定工具；每个已放置木箱拥有 16 个独立槽位。
- 道路、围栏与火炬只能放在种植区外的家园空地；洒水器只能放在未开垦种植床。道路不阻挡移动，围栏、火炬和洒水器阻挡对应格。
- 树木和水晶采集后从地图暂时消失，并以稳定格 ID 和耗尽日期写入存档；重新读档不会提前出现，达到各自再生天数后恢复，耗尽期间所在格可通行。

## 目标预览

- `GameSession.PreviewSelectedTarget` 是工具目标预览的唯一业务入口，只读取当前工具、目标、体力、水量、种子和背包容量，不修改状态。
- `TargetPreview` 同时返回真实目标格、状态、对象种类和本地化动作键；实际动作继续由 `UseSelected` 与场景交互事件执行。
- 青绿色表示当前可按 `E` 执行，暖金色表示需要更换工具或物品，玫红色表示体力、水量、种子或背包容量不足，普通格只显示弱化目标框。
- `TargetPreviewKind` 区分地面、土壤、作物、果树、蜂巢、树、晶体、水面、地标、人物、门、设施、邮箱、储物箱、道路、围栏、火炬、洒水器、委托板、星灯台和床；`TargetCursor` 按对象实际轮廓绘制高亮，而非始终绘制同一格方框。
- NPC、门、商亭、三台加工机、星辉货箱、星光邮箱、星织储物箱、星灯委托板和林地守望星灯保留邻接交互，但高亮位置会吸附到真实对象，和按键判定保持一致；这些设施必须选择“手”才能执行，工具不匹配时显示暖金色提示。
- 选中星织储物箱时，预览与实际放置共同读取 `StorageSystem.CheckPlacement`；农田、阻挡格、固定设施和已有木箱会显示相同的不可放置原因，失败不消耗木箱。
- 仓库根目录 `AGENTS.md` 将这套规则设为后续交互功能的项目约束：新增钓鱼、采矿、开箱或设施时，必须同步补齐预览、动作、轮廓、本地化和测试。

- 世界为 192×128 格，按 32×32 格划分为 6×4 个稳定区块；运行时只保留玩家当前区块及周围 3×3 邻域，越界区块立即卸载。
- 原有 48×32 农场保留为世界左上角家园区；微光城迁移并扩建到中央 `(64,32)–(127,95)`，中心 `(96,64)` 通过东西、南北放射道路连接六个外围区域。

## 验证重点

1. 无效工具目标不得消耗体力。
2. 只有当天已浇水作物在睡眠时成长。
3. 浇水状态每日清除，成熟作物正确收获。
4. 任务阶段严格按交谈、耕作、播种、浇水、成长、收获、交付推进。
5. 存档往返后日期、体力、快捷栏、农田、任务和语言一致。
6. 中英文键集合完整。
7. 地图装饰不得遮挡可耕格、NPC、目标光标或 HUD。
8. 六块视觉农田与 `FarmSystem.IsPlantingBed` 必须保持坐标一致。
9. 生成背景只能承担静态环境表现，作物、浇水和任务状态必须继续由业务模型驱动。
10. 玩家四方向站立、双步态切换、靴底与阴影接触、米菈显示、两类作物全成长阶段与红色色键边缘必须进行实机检查。
11. 门口信标的视觉提示必须与邻接交互范围一致。
12. 交易失败不得扣除微光币或物品；背包满时购买必须保持原状态。
13. 加工必须按投入两份作物、过夜一次、主动领取的顺序推进；背包满时保留待领取状态。
