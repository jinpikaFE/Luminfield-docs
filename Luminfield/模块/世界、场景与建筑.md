# 世界、场景与建筑

## 世界基线

- 大世界为 192×128 格，家园农场为 48×32 格，基础瓦片 16×16。
- 世界划分为家园农场、低语林地、星落草甸、微光村、晶辉谷、月水湿地和星落遗迹七个区域。
- `WorldDefinition` 定义世界尺寸、道路、区域、地标、碰撞和稳定区块 ID。
- `WorldChunkStreamer` 只投影玩家周围 3×3 个 32×32 区块；卸载不改变领域状态。
- `WorldSeasonVisualCatalog` 按 `CalendarSystem.SeasonId(day)` 选择基础、雨幕、星熟或长夜 profile；季节边界只把地表调色与同注册探索图集推送到当前区块，不卸载或重建区块。
- `ExplorationSystem` 只保存稳定区块 ID，迷你地图由该状态投影。

## 稳定场景

`PlayerLocationIds` 当前包含：

- `world`
- `cottage`
- `moonlit_archive`
- `moonstone_workshop`
- `starweaver_tea_house`
- `twilight_emporium`
- `starlight_post`
- `starfall_watch`
- `greenhouse`
- `starfeather_coop`
- `moonfleece_barn`
- `starharvest_market`
- `gleamrise_planting_festival`
- `longnight_lantern_feast`
- `firefly_tide`
- `crystal_grotto_survey`
- `starfall_ruins_trial`

新增场景必须增加稳定 ID、合法入口/出口、保存恢复、未知 ID 回退、碰撞与玩家安全落点测试；不得继续扩展布尔 `InsideX` 作为存档真相。

`crystal_grotto_survey` 是阶段 F 为解除晶谷依赖而接入的固定五室 U 形勘探场景，
不是阶段 E 的程序生成矿洞。世界入口/返回格为 `(72,85)/(72,86)`，内景出口/安全点
为 `(20,20)/(20,18)`；升级台、休眠封脉、17 个矿脉格与第 5 室勘探锚由稳定目录
驱动。背景只画空承座，矿脉、封脉、锚点、耗尽、工具阶级和里程碑全部由运行时状态投影。

`starfall_ruins_trial` 是阶段 F 为闭合遗迹稳定依赖而接入的固定三室试炼场景，不是
阶段 E 的程序生成矿洞或完整战斗体系。世界入口要求晶谷星灯奖励，内景包含底部安全
入口、月纹短刃架、三间战斗房、6 个稳定敌人实例与四处遗物台；敌人临时生命/位置、
攻击/闪避冷却和玩家试炼生命属于当前尝试，净空房间、短刃领取、遗物取得与捐赠进入
schema-v1 加法存档。失败在次日 06:00 回到小屋并恢复劳动体力，不能扣除遗物或已净空房间。

`starfall_sixfold_gate` 当前不是稳定场景或业务实体，只是 2×2 素材准备稿。后续接入必须
另行补齐稳定 ID、Core 状态、统一目标预览、实际动作、入口/出口、传送、存档与双语测试，
不能从第六灯奖励或点亮图推断星门已经存在。

## 建筑契约

- 外门、室内出口和设施使用统一目标预览，并与实际开放时间、工具和邻接规则一致。
- 室内静态通行几何与 NPC 寻路读取同一 Core 定义。
- 只读设施只展示说明，不隐式增加购买、配方、任务、收费、物品或奖励。
- 建设施工使用 `ConstructionCatalog.Projects` 的稳定有序项目 ID；项目各自保存阶段与剩余夜数，但全局同时只允许一个项目施工中。
- 开工先完整检查访问位置、项目状态、金币和材料，再以一次可观察提交原子扣除；睡眠只推进当前在建项目。
- `homestead_workshop` 完成后，家园 `(42,9)` 的真实工作台启用；邻接预览与打开动作复用同一 `GameSession` 检查，并用专用轮廓覆盖蓝图、施工和完成实体，而不是玩家脚下格。
- `homestead_greenhouse` 要求家园工坊已完成；家园门格 `(38,10)` 只有在四夜施工完成后可进入，室内出口 `(20,20)`、安全点 `(20,18)` 与蓄水池 `(7,14)` 均读取同一 Core 布局和专用目标轮廓。
- `homestead_starfeather_coop` 无工坊前置；家园门格 `(6,10)` 在三夜完成后开放，返回点 `(6,11)` 永久可达。室内出口 `(20,20)`、安全点 `(20,18)`、饲槽 `(9,13)`、巢箱 `(32,10)` 与动物锚点 `(20,13)` 均读取同一 Core 布局和专用真实对象轮廓。
- `homestead_livestock_automation` 显式要求家园工坊、星羽鸡舍和月绒畜棚完成；四夜后两座内景的 `(8,17)` 控制台启用。控制台只投影分建筑饲料/产品缓冲，施工状态仍由 `ConstructionSystem` 唯一持有。
- `cottage_second_upgrade` 显式要求第一次小屋升级和家园工坊；960 微光币、32 微光木、14 晶辉碎片原子支付，四夜后把既有预留区拆分为真实月炉厨房 `(29,14)` 与食材柜 `(34,14)`，不改变房壳、出口和通行碰撞。
- 旧施工根字段只镜像第一次小屋升级；家园工坊、月露温室和后续项目不得写入旧槽位。
- 新碰撞不能卡住旧档玩家；布局变化必须提供安全位置归一化。
- 场景 View 不保存第二份门状态、施工进度、人物位置或任务状态。

## 世界资源

- 工具、目标、体力、容量和耗尽状态在采集前完整检查。
- 水晶第 2 天再生，树木第 7 天再生；林地守望星灯奖励只把低语林地树木缩短到 4 天。
- 节点身份使用稳定资源 ID；图像位置只负责显示。
- 旧 `RemovedNodes` 迁移为按载入日开始的安全再生记录。

## 验证

- 世界尺寸、区域、道路、稳定区块和越界行为的领域测试。
- 区块加载始终限制在 3×3，连续跨区不改变玩家坐标或业务状态。
- 每个门验证开放边界、错误工具、关闭状态、存档恢复和出入口安全落点。
- 地标、区块缝隙、迷你地图、生成建筑裁切和碰撞变化必须在 macOS 实机检查。
- 日 14/15、28/29、42/43 边界必须让已加载与新加载区块使用同一季相；资源坐标、阻挡、耗尽状态、掉落与天气覆盖保持不变。
- 日 56/57 与跨年窗口同样验证长夜 profile 的进入/退出；截图 373 已目检长夜六区表现。
- 固定遗迹试炼必须验证入口前置、短刃容量、移动后真实攻击范围、三类攻击、闪避无敌帧、失败恢复、净空持久化、遗物原子取得/捐赠和第六灯；截图 367–372 已目检运行时表现。
