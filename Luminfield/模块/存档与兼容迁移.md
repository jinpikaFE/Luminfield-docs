# 存档与兼容迁移

## 当前契约

- 存档模型为 `GameSaveV1`，当前 `SaveService.CurrentSchemaVersion = 1`。
- 正常运行时写入 Godot `user://saves/slot_1.json` 对应路径。
- JSON 使用 camelCase、枚举字符串和大小写不敏感读取。
- 新系统优先继续向 `GameSaveV1` 添加带安全默认值的字段；版本号不是每新增字段就递增。

## 写入路径

1. `GameSession.Capture()` 从所有状态所有者取得独立投影。
2. `SaveService.Save` 写入同目录临时文件。
3. 临时文件完整落盘后，通过 `File.Move(..., overwrite: true)` 原子替换正式存档。
4. 场景节点引用、翻译文本、纹理、瞬时路径和 UI 展开状态不进入存档。

## 读取路径

1. 文件不存在返回 `Missing`。
2. 反序列化后，版本高于当前支持值返回 `Unsupported`，不猜测降级。
3. 版本小于等于 0 的旧数据提升到当前 v1 兼容路径。
4. `SaveService.Normalize` 补空对象、过滤未知 ID、去重、限幅并迁移旧字段。
5. `GameSession.Restore` 把归一化投影交回各领域系统重建运行时状态。
6. 损坏 JSON 保留为 `.broken-时间戳`，返回 `Corrupt`，不静默覆盖原文件。

## 已存在的兼容规则

| 旧数据 | 当前处理 |

| `Player.InsideCottage` | 在 `LocationId` 缺失时迁移到 `cottage`；其他未知地点回退 `world` |
| 旧工具 `hoe` | 迁移为固定工具顺序中的 `shovel`，保留其他物品 |
| 缺失的新投影 | 使用空列表或系统默认值，不清除日期、体力、库存、农田和任务 |

| 旧 `RemovedNodes` | 从载入日建立安全资源再生记录 |
| 旧单队列 `ProcessorSave.RecipeId` | 仅在没有合法现代机器记录时迁入主机器 |
| 非法事件顺序 | 按人物事件链独立过滤，不牵连其他合法链 |
| 旧档缺少阶段 F 新人物 | `Village`、`Mail` 与 `CharacterEvents` 继续使用既有稳定 ID 列表；哈尔登、玛维娅、西芙伦和多里克获得未认识/0 关系/无事件/无邮件的安全默认值，未知人物与未知事件仍过滤，schema 保持 v1 |
| 旧档已有凯尔/塞菈/奥林第二事件但缺关系回信 | 新目录加载后在下一次跨日按完成日补投一次；艾洛温/维莎必须先完成新增两阶段事件，不按关系点直接补信；DTO 与 schema 保持 v1 |

| 旧档缺少大世界季相字段 | 不需要迁移：季相只从既有绝对 `Day` 派生，纹理路径、调色 profile 与当前区块缓存都不进入 `GameSaveV1`；资源耗尽、探索和位置状态原样保留 |
| 旧档缺少或只有阶段 23 的 `Collection` | `Initialized=false` 时为所有当前分类做一次证据型回填；旧 `Initialized=true` 且缺 `InitializedCategoryIds` 时只把 `codex_crops` 视为已初始化，并为新增 `codex_cooking` 回填一次。证据来自背包、木箱、食材柜、货箱待售/最近结算、节日结果、星灯贡献、当前加工输入和教程收获计数；不能证明的历史售出/食用物不虚构，schema 仍为 v1 |
| 非法专精或越界经验 | 通过 `FarmingSkillSystem.NormalizeSave` 归一化 |
| 缺失或非法 `Orchard` | 缺失时恢复为空果园；未知果树/辉巢 ID、重叠占位和越界位置在归一化时过滤 |
| 旧 `Construction` 根字段 | 只提升和镜像第一次小屋升级；新 `Projects` 按稳定项目 ID 合并，未知项目过滤，同 ID 完成态优先，否则保留最接近完成的合法施工态；损坏档出现多个施工中项目时只保留 Catalog 顺序中的第一个 |
| 缺失或损坏 `Greenhouse` | 缺失时恢复为空温室；只保留 24 个合法床位并按坐标去重，未知作物清为合法空耕地；未完成温室却记录室内位置时安全回到家园门外，合法隐藏耕地不因建筑记录缺失而删除 |
| 缺失或损坏 `Animals` | 缺失时恢复为空动物组合；只保留目录登记且具备真实投影的三只固定首发实例，过滤未知/重复及物种/建筑不匹配记录，并限幅年龄、心情、日期与对应产物家族；不因施工记录缺失删除合法动物。缺失 `Automation` 时按两栋建筑建立空缓冲，过滤未知建筑/产物并限幅饲料 28、产品 12，绝不复制既有 pending；未完工建筑却记录室内位置时安全回到各自门外 |
| 缺失或损坏 `Kitchen` | 缺失时恢复为空 24 格食材柜；只保留合法食材稳定 ID，重复堆叠确定合并并按 MaxStack/24 格限幅。即使第二次小屋升级记录缺失也保留 pantry 内容但隐藏入口，不反向赠送施工完成态 |
| 缺失或损坏 `Mining` / `ToolProgression` | 缺失时恢复为空矿脉耗尽记录和基础铲阶；未知/重复矿脉或工具阶级过滤，未来日期与非法阶级归一。青铜星纹铲只以稳定 `shovel` 的等级状态保存，不替换背包工具 ID；第 5 室锚和晶谷星灯分别由各自稳定里程碑/星灯组合保存，schema 保持 v1 |

## 必须保持的不变量

- 旧档读取不得丢失既有日期、体力、背包、作物、任务、探索、关系或资源状态。
- 未知新版本不得按旧结构强行读取。
- 读取不得重新随机决定已经保存的作物品质、天气共鸣或确定性奖励。
- 归一化必须可重复执行；重复读取同一存档不应继续改变合法数据。
- 新增稳定实体必须同时定义未知 ID 的处理方式。
- 迁移失败不能直接覆盖原始文件。

## 新增持久化状态检查表

- 在 `Models.cs` 增加带安全默认值的 DTO。
- 在状态所有者实现 `Capture`、`Restore` 和必要的 `NormalizeSave`。
- 接入 `GameSession.Capture/Restore`。
- 在 `SaveService.Normalize` 补空、过滤、限幅和旧字段迁移。
- 测试新档、缺字段旧档、未知 ID、重复记录、边界值、保存往返和损坏文件。
- 明确该字段是否真的需要持久化；可从其他稳定状态推导的值不重复保存。

## 当前存档投影

`Player`、`Inventory`、`FarmTiles`、`Greenhouse`、`Animals`、`Kitchen`、`Collection`、`Mining`、`ToolProgression`、`Quest`、`Coins`、`Processor`、`Exploration`、`Resources`、`Weather`、`Shipping`、`Storage`、`FarmObjects`、`Orchard`、`Commission`、`WeeklyCommission`、`Starlight`、`Village`、`Mail`、`CharacterEvents`、`Construction`、`Festival` 和 `FarmingSkill`。

`CollectionSave` 继续使用 schema-v1 加法根保存 `Initialized`、`InitializedCategoryIds`、已发现条目 ID 和已领取奖励 ID。作物条目直接复用 20 个基础作物稳定 ID，普通/莹润/星辉与两类共鸣产物统一归一；料理条目直接复用四道成品稳定 ID。20/20 和 4/4 分别只使 `codex_reward_moonlit_almanac`、`codex_reward_moonhearth_recipe_journal` 可领取，不在读取或归一化时自动授予，重复领取和损坏档重试均不得产生第二份状态。

`FestivalSave` 继续使用 schema v1 加法字段：legacy `Scrip` 只表示星熟集市券，`Results` 按节日 ID/年份保存已完成结果，`PlantingAttempts` 保存芽辉播种祭未完成的选种、开始时间与真实花田格，`CurrencyBalances` 按稳定货币 ID 保存独立花辉币与灯愿结。长夜灯宴结果沿用年度记录并增加 `GiftItemId`、`GiftRewardItemId`、`RitualId`；只有最终共辉星仪原子成功才写结果，不保存 UI 内的半完成选择。旧档缺字段时归一为空；未知节日、物品、仪式、种子、花田格和货币过滤，重复记录确定合并。恢复到已过期限或闭场时间的节日位置会安全送回微光村，不清除普通背包、日期或其他节日结果。

第三座 `starlight_meadow` 继续复用 schema-v1 `Starlight.Pedestals` 组合，不新增存档根或节庆完成布尔。花卉与动物产物节点保存稳定家族贡献；节庆回响进度每次从归一化后的 `Festival.Results` 只读派生，不复制花辉币、集市券或结果记录。legacy 星灯根字段仍只镜像林地，旧两灯存档会确定性补出空草甸状态；远香授粉只从草甸整灯完成态派生，不保存第二个奖励布尔。
