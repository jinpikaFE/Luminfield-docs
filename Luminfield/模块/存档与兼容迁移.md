# 存档与兼容迁移

## 当前契约

- 存档模型为 `GameSaveV1`，当前 `SaveService.CurrentSchemaVersion = 1`。
- 正常运行时写入 Godot `user://saves/slot_1.json` 对应路径。
- JSON 使用 camelCase、枚举字符串和大小写不敏感读取。
- 新系统优先继续向 `GameSaveV1` 添加带安全默认值的字段；版本号不是每新增字段就递增。

## 写入路径

1. `GameSession.Capture()` 从所有状态所有者取得独立投影。
2. `SaveService.Save` 写入同目录临时文件。
3. 临时文件完整落盘后，通过 `File.Move(..., overwrite: true)` 原子替换正式存档。
4. 场景节点引用、翻译文本、纹理、瞬时路径和 UI 展开状态不进入存档。

## 读取路径

1. 文件不存在返回 `Missing`。
2. 反序列化后，版本高于当前支持值返回 `Unsupported`，不猜测降级。
3. 版本小于等于 0 的旧数据提升到当前 v1 兼容路径。
4. `SaveService.Normalize` 补空对象、过滤未知 ID、去重、限幅并迁移旧字段。
5. `GameSession.Restore` 把归一化投影交回各领域系统重建运行时状态。
6. 损坏 JSON 保留为 `.broken-时间戳`，返回 `Corrupt`，不静默覆盖原文件。

## 已存在的兼容规则

| 旧数据 | 当前处理 |
| --- | --- |
| `Player.InsideCottage` | 在 `LocationId` 缺失时迁移到 `cottage`；其他未知地点回退 `world` |
| 旧工具 `hoe` | 迁移为固定工具顺序中的 `shovel`，保留其他物品 |
| 缺失的新投影 | 使用空列表或系统默认值，不清除日期、体力、库存、农田和任务 |
| 未知/重复稳定 ID | 按对应 Catalog 过滤、去重并限幅 |
| 旧 `RemovedNodes` | 从载入日建立安全资源再生记录 |
| 旧单队列 `ProcessorSave.RecipeId` | 仅在没有合法现代机器记录时迁入主机器 |
| 非法事件顺序 | 按人物事件链独立过滤，不牵连其他合法链 |
| 非法专精或越界经验 | 通过 `FarmingSkillSystem.NormalizeSave` 归一化 |
| 缺失或非法 `Orchard` | 缺失时恢复为空果园；未知果树/辉巢 ID、重叠占位和越界位置在归一化时过滤 |

## 必须保持的不变量

- 旧档读取不得丢失既有日期、体力、背包、作物、任务、探索、关系或资源状态。
- 未知新版本不得按旧结构强行读取。
- 读取不得重新随机决定已经保存的作物品质、天气共鸣或确定性奖励。
- 归一化必须可重复执行；重复读取同一存档不应继续改变合法数据。
- 新增稳定实体必须同时定义未知 ID 的处理方式。
- 迁移失败不能直接覆盖原始文件。

## 新增持久化状态检查表

- 在 `Models.cs` 增加带安全默认值的 DTO。
- 在状态所有者实现 `Capture`、`Restore` 和必要的 `NormalizeSave`。
- 接入 `GameSession.Capture/Restore`。
- 在 `SaveService.Normalize` 补空、过滤、限幅和旧字段迁移。
- 测试新档、缺字段旧档、未知 ID、重复记录、边界值、保存往返和损坏文件。
- 明确该字段是否真的需要持久化；可从其他稳定状态推导的值不重复保存。
