# 架构总览

## 目的

本文定义 Luminfield 当前不可随单个功能任务改变的架构骨架。实现细节仍以仓库为准；当新功能需要改变依赖方向、状态所有者、存档策略或动作语义时，必须先形成明确决策，而不是在场景代码中增加旁路。

## 技术与运行边界

- Godot 4.7.1 .NET、C#、`net8.0`，SDK 由 `global.json` 固定。
- 内部分辨率 640×360，基础瓦片 16×16，最近邻像素表现。
- 桌面目标为 macOS、Windows 和 Linux；当前不包含 Web、移动端或主机。
- 世界、角色、文本、代码、美术和音频保持原创。

## 四层结构

| 层 | 主要位置 | 负责 | 明确不负责 |
| --- | --- | --- | --- |
| 数据目录 | `src/Core/Definitions.cs` 与各 Catalog | 稳定 ID、静态定义、配方和配置 | 保存玩家进度、持有场景节点 |
| 领域层 | `src/Core/` | 规则、状态、校验、归一化、存档投影 | 绘制、节点查找、输入设备差异 |
| 会话编排 | `GameSession.cs` | 组合领域系统、跨系统动作、跨日顺序、位置和事件 | 复制 UI 状态、硬编码场景节点 |
| 表现层 | `src/Game/` | 输入转发、世界/室内/HUD 投影、视觉与音频 | 维护第二份农业、NPC、经济或任务真相 |

## 运行时主路径

1. 输入层把“选择、移动、使用、打开、确认”转换为意图。
2. 场景把意图与目标位置交给 `GameSession`。
3. `GameSession` 根据当前场景、选中物、领域状态和目录定义调用对应系统。
4. 领域系统先检查完整前置条件，再一次提交状态变化。
5. `Changed`、`EnergyChanged`、`DayEnded` 等事件通知表现层重新投影。
6. UI 只读取结果和本地化键，不反向定义业务规则。

## 核心不变量

- `GameSession` 是唯一全局业务入口；场景不得直接拼装跨系统写操作。
- `Core` 不依赖具体 Godot 场景节点。
- 稳定实体使用 ID；存档不保存翻译文本、节点引用或瞬时寻路缓存。
- 预览和实际动作读取同一套目标、工具、资源、容量和开放条件。
- 失败动作不扣体力、水量、物品或货币，也不推进地图、任务、关系、技能或存档状态。
- 多资源变更先模拟完整结果，再一次提交；不得先扣后补。
- 生成素材只承担视觉表现，业务状态由领域模型驱动。
- 中英文使用同一键集合；玩家可见文本不得只在场景中硬编码。
- 新持久化状态采用兼容旧档的加法字段，并在读取时归一化。

## 事实来源

- 架构入口：`src/Core/GameSession.cs`
- 状态投影：`src/Core/Models.cs`
- 存档边界：`src/Core/SaveService.cs`
- 静态目录：`src/Core/Definitions.cs` 与各系统 Catalog
- 场景编排：`src/Game/Main.cs`
- 项目硬规则：仓库根目录 `AGENTS.md`

## 何时更新本文

- 新增架构层、全局服务或跨系统入口。
- 改变 `Core` 与 `Game` 的依赖方向。
- 改变稳定 ID、存档版本、原子动作或本地化边界。
- 引入新的平台、渲染分辨率或资产生产方式。
