# 交互预览与原子动作

## 双入口契约

- 预览入口：`GameSession.PreviewSelectedTarget(GridPosition)`。
- 动作入口：`GameSession.UseSelected(GridPosition)` 及同类明确业务方法。
- 两者必须读取同一当前场景、目标对象、选中工具、体力、水量、库存容量、开放时间和领域状态。
- 预览只返回 `TargetPreview`，不得修改任何业务状态。

## 预览语义

| 状态 | 视觉 | 含义 |
| --- | --- | --- |
| `Available` | 青绿色真实对象轮廓，显示 `E · 动作` | 当前输入可成功执行 |
| `NeedsTool` | 暖金色真实对象轮廓 | 目标可交互，但当前工具不匹配 |
| `Blocked` | 玫红色真实对象轮廓 | 体力、水量、种子、材料、营业或容量等条件不足 |
| `Neutral` | 弱化目标框 | 当前目标没有可执行动作 |

`TargetPreviewKind` 区分土壤、作物、果树、蜂巢、树、水晶、水面、人物、门、设施、委托板、木箱、放置物、床和厨房等范围。邻接交互必须高亮真实对象位置，不能退回玩家朝向的无关格。

## 动作提交顺序

```text
识别目标与动作
  → 检查场景 / 工具 / 状态
  → 检查体力、水量、货币、材料和容量
  → 在副本上模拟多资源结果
  → 一次提交领域状态
  → 记录任务/技能等成功后派生进度
  → 发出 Changed 事件
```

## 原子业务模式

- `Inventory.TryExchange`：先在克隆槽位上移除全部输入并加入完整产出，再提交。
- `TryRemoveMany`、`TryRemoveFamilies`、`TryAddMany`：整组成功或整组不变。
- 加工机批量领取：先模拟全部就绪产物，任一放不下时所有机器和背包均不变。
- 委托、星灯、建设和商店：先完成材料、容量、货币、营业与状态检查，成功后再修改奖励/进度。
- 果树与辉巢：先检查季节、工具、目标占位、树苗/蜂巢数量、邻近成熟树、可采摘/可领取状态和背包容量，成功后再扣物、改变果园状态或加入产物。
- 体力、浇水壶水量、种子和耕作经验只在对应动作成功后变化。

## 失败零副作用

失败时不得：

- 扣体力、水量、物品或货币；
- 发放部分产物或只移除部分材料；
- 修改农田、资源耗尽、机器、施工、委托、星灯、邮件或关系状态；
- 增加教程、委托、技能或角色事件进度；
- 写入新的存档事实。

## 新交互必须成套交付

1. 只读预览规则。
2. 实际动作规则。
3. 对象轮廓或真实范围。
4. 简体中文与英文动作/失败键。
5. 可执行、工具不匹配、资源不足和容量不足测试。
6. 若有视觉变化，在 macOS 640×360 最近邻画面中实机查看。

## 验证矩阵

| 情况 | 预览 | 动作 | 状态 |
| --- | --- | --- | --- |
| 条件完整 | `Available` | 成功 | 仅发生预期变更 |
| 工具错误 | `NeedsTool` | 失败 | 完全不变 |
| 资源不足 | `Blocked` | 失败 | 完全不变 |
| 容量不足 | `Blocked` | 失败 | 输入与产出均不变 |
| 目标已完成/耗尽 | `Blocked` 或 `Neutral` | 失败 | 不重复结算 |
| 保存往返 | 与动作规则一致 | 结果可复现 | 不重抽、不重复发奖 |
