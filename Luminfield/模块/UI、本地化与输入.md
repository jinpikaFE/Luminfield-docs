# UI、本地化与输入

## 职责边界

- UI 展示 `GameSession` 和领域系统的当前投影，转发用户意图并订阅变化事件。
- UI 不决定金币、库存、作物成熟、NPC 日程、任务完成或存档状态。
- `Main.cs` 编排标题、农场/室内、HUD、对话、暂停、结算和覆盖层。
- 各 `*Ui.cs`、`UiViews.cs` 和 `*View.cs` 只维护节点生命周期与视觉状态。

## 视觉基线

- 640×360 内部分辨率，默认窗口 1280×720，最近邻过滤。
- 暮色靛蓝、发光青绿、暖金色为主色；玫红用于资源/容量阻塞。
- 玩家频繁操作保持直接可达；覆盖层必须处理层级、焦点、关闭和输入隔离。
- 目标高亮必须覆盖真实对象轮廓，并使用统一 `TargetPreviewState` 颜色语义。

## 本地化契约

- 简体中文与英文分别位于 `localization/zh_CN.json` 和 `localization/en.json`。
- 两个文件必须拥有完全相同的键集合；当前验证快照为 770/770。
- 领域结果返回稳定本地化键，不保存已翻译文本。
- 动作、失败原因、物品、作物、人物、设施、对话、面板和验证场景都必须双语。
- 新键应按现有命名空间归类，不能以 UI 中硬编码文本替代。
- 存档只保存 Locale 选择和稳定业务 ID。

## 输入契约

- `InputSetup.cs` 统一建立键鼠和手柄动作。
- 移动、交互、快捷栏、背包、制作和暂停使用逻辑动作，不在业务系统中判断具体按键。
- 场景负责把玩家朝向或邻接目标转换为 `GridPosition`；领域负责判断该目标是否可执行。
- 打开覆盖层时必须避免同一次输入穿透到底层世界动作。
- 正常启动与开发试玩入口必须共用业务路径；试玩只预置状态，不改动作规则。

## 失败与反馈

- 失败文本来自 `ActionResult.MessageKey` 或 `TargetPreview.ActionKey`。
- UI 可以显示提示和音效，但不能因为播放失败反馈而改变业务状态。
- 容量不足、工具错误、闭店和资源不足必须在动作前可见，并与实际失败原因一致。

## 验证

- 检查中英文键集合完全一致，不仅检查 JSON 可解析。
- 关键面板至少覆盖打开、关闭、空态、满容量、阻塞态和恢复存档后的状态。
- 目标高亮、像素缩放、文字遮挡、覆盖层层级和布局变化必须在 macOS 实际画面检查。
- 键鼠与手柄动作映射的静态存在不等于对应硬件已经实机通过。
